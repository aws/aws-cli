# Known native gaps, launcher differences, and upstream issues for this
# directory's run.py. A `parity-gap` entry is a test the public AWS CLI of
# the in-tree version passes and the built binary fails on its native route;
# the built binary passes it on the Python route. A `launcher-difference`
# entry is a test the public AWS CLI passes and the built binary fails on
# both routes, because the launcher both share deliberately differs from the
# public AWS CLI's. An `upstream-issue` entry is a repo test every binary
# fails because the released AWS CLI has the behavior the test rejects.
#
# The run against the built binary marks every entry as a strict expected
# failure on the routes it fails on, so a gap that closes fails the run until
# its entry goes: by default every entry, and with
# `--env AWS_CLI_NATIVE_ROUTER=python` every entry but the parity gaps. A
# run against another AWS CLI applies only the upstream issues here: that
# binary must pass every other test but the ones upstream-failures.txt
# lists. Each entry has one pytest node id followed by its category and the
# reason.
#
# Rebaseline from `--run-all` and `--junit-dir` reports of the built binary
# on both routes and of the public AWS CLI, comparing the three.
